# Live Controls component playground

Live Controls is a shared primitive component playground on browser Wasm/WebGL and native GLES2. Home opens it at `#/controls`. It contains a horizontal slider, a rotary dial with a 270-degree travel, and a two-dimensional touch pad. The output toggle changes the shared demo flag and component palette; it is not a hardware actuator. Reset restores the three shared defaults and clears this host's local pad trail.

## Components and gesture ownership

The scene is a typed FlexBuffers module asset, `shell-assets/playground.flex`, generated by `dashboard-shell-assets`. Canvas, Superellipse, Circle and Text primitives compose every component. The slider, dial and pad are templates with a `DragControl` responder. They use the same target-to-parent responder chain and captured, snapshot-pinned coordinates as the rest of the shell.

A press captures the responding component. Moves and releases continue outside its bounds, with values clamped to the valid range. A missing/rebound responder produces cancellation. Only one local pointer can own one component at a time; separate controls can be dragged simultaneously. The dial ignores positions near its centre, where the angle is ambiguous. Its lower dead zone clamps to the corresponding end of its travel.

Pressed highlights, pointer IDs, gesture feedback, pending values and the last twelve pad positions belong to the local interaction owner. They do not enter shared history. The touch-pad trail is local; other screens see the shared crosshair point. On cancellation, an unpublished preview is discarded while already published values remain. No gesture rollback overwrites another device's edits.

Shared writes are capped at one per 50 ms per active component, with exact press/release publication. Local previews can update between these writes. A background host tick flushes the latest pending value rather than publishing every pointer sample. The native state transport retains its existing 100 ms coalescing interval, so it may skip intermediate shared values. These are bounded publication policies, not a touch-latency or display-FPS measurement.

## Shared values

Slider and dial use independent integer CRDT registers in 0..1000. The pad uses one four-byte little-endian pair of uint16 values in the same range. Concurrent slider and dial edits merge independently; concurrent pad edits select a complete pair rather than mixing X and Y. All peers validate values before activating a view. The public server validates each new CRDT operation, including losing conflicts, and allows these specific demo registers without allowing layout/schema administration.

Browser assistive controls expose slider/dial roles and current values. Arrow keys adjust them in five-percent steps. The touch pad supports horizontal and vertical arrow adjustments; its accessible label includes both coordinates. Assistive activation advances a control by ten percent. Physical frame interaction uses calibrated evdev touch through the same Rust controller.

## Layout Lab and navigation

**Layout Lab** opens the earlier editable dashboard inside Live Controls at `#/controls/layout`. It continues to render the existing collaborative `/layout` register, preserving that binary layout experiment. Back first returns to the component playground, then Home. Public visitors can view and interact with the demo, but editing the layout itself still requires the private administrative interface. The new playground asset ships with the signed code module; a general live module/catalog editor remains later work.

## Validation

Core checks cover independent-register convergence, atomic pad pairs, invalid values, drag capture outside the original target, cancellation, bounded publication, exact release values, zero/small/full slider geometry and local Back navigation. Real-process public sync tests send all three values into the same authority used by trusted hosts while retaining the private Monitoring presentation. Native readiness includes the three shared values after an acknowledged frame, making convergence inspectable without treating a socket connection as rendering evidence.

Browser checks exercise the actual compiled Wasm controls and keyboard semantics. Native touch acceptance remains a physical-device check; existing keyboard acceptance and earlier 3D frame-rate measurements are not acceptance of these new components.
